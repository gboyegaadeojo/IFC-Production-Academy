# Admin: curriculum

**Curriculum** is where you build courses, for a topic or for a level in a department. You publish your own department's work. Nobody else has to approve it, unless your department has turned on review before publishing.

## Topics and departments

The row of buttons at the top starts with the **topics**, then a divider, then the **departments**.

- A **department** is a team. Its courses sit in three levels, and they can have practical assessments.
- A **topic**, such as General or Leadership, is courses for anyone on the production team. Some topics use levels and some are one list. Topics have lessons, quizzes, versions, and certificates, but no practical assessments, so the Practicals tab doesn't appear.

Production Directors build and publish topics. You add a topic under [Departments](admin-people.md#departments).

## Formatting text

The course summary, lesson summary, and lesson text work like a word processor. Use the buttons above the text for **Bold**, **Italic**, **Underline**, **Heading**, **Subheading**, lists, and **Link**. Links need to start with `https://`.

If you paste text that has `#` or `**` markers, they turn into real formatting. Volunteers see the same formatting on the course and lesson pages. Summaries can be up to 5,000 characters and lesson text up to 20,000, and the count under each box shows how much you've used.

## The key idea: drafts and versions

Changes stay in a draft until you publish, and volunteers keep seeing the live version until then. Each publish is kept as a version you can go back to. People's progress stays linked to the version they earned it on, so publishing never rewrites anyone's history.

## Making a course

1. Choose **Add course** under a level, and give it a title.
2. Fill in **Course details:** a summary and objectives.
3. Add a module, then add lessons to it.
4. Add a quiz and a practical if the course needs them.
5. **Publish,** with a change note saying what changed.

To change a published course, choose **Edit course**. That starts a new draft.

If you make a course by mistake and it's never been published, you can delete it from its row's menu. A course people have learned from can only be archived: volunteers stop seeing it, and its versions and everyone's history are kept.

## Lessons

| Field | Notes |
| --- | --- |
| **Title, module, summary** | What it is and where it sits |
| **Objectives** | One per line. Shown as "By the end of this lesson" |
| **Estimated minutes** | Optional |
| **Video** | Optional. Either YouTube (unlisted) or the church video library. For YouTube, paste the link from the Share button |
| **Resources** | Attach this department's SOPs. The lesson always shows each SOP's current version |
| **Required to complete the course** | Leave it on unless the lesson is optional |

Learners mark lessons complete themselves. The app never claims a video was fully watched.

## Quizzes

Set where the quiz sits, and its rules: the pass mark (80% to start with), how many attempts (3 to start with), whether correct answers are shown, whether questions shuffle, and whether it must be passed to finish the course.

Add questions with **Add question**. A quiz without questions can't be published. A question has a type, its answers, which one is correct, and an optional explanation shown with the correct answers when the quiz allows.

The app scores every attempt. Nobody marks them by hand. If someone runs out of attempts, open **Results** and choose **Give another attempt**, with a note such as "Went through camera presets together".

## Practical assessments

A practical is a checklist an observer ticks while watching someone work.

1. **Add to checklist:** something they can watch happen, not a feeling, such as "Frames the speaker with headroom". Mark each item as required or not.
2. **Settings:** where it sits, which competency a pass grants, and the pass rule. The usual rule is that every required item must be observed.

The observer ticks what they saw, and the Academy works out **Pass** or **Not yet** from your rule. See [Assessments and competencies](admin-assessments.md).
